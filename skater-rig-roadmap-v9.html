SKATER-RIG v9: THE NEW SKELETON GOES LIVE

Two weeks ago this game was one giant HTML file with a stick figure in it. Today the stick figure has a brand-new skeleton, a full animation system, its own editor, 16 automated test gates — and as of this week, the new skeleton is the one actually driving the game you play.

16 / 16 test gates green (168 checks) v1.1.0 — the rig-v2 release, going out now 164 commits since July 8 34 puppet parts, 13 animation clips
the whole thing in plain words

What is this? KICK/PUSH is a hand-drawn skateboarding game. You swipe to push, tap to jump, and rack up points doing flips and grinding rails before the clock runs out. It's one single web page — no app store, no install — live at play.usefulpurpose.com.

What's been happening? The skater's original "skeleton" (the code that bends his arms and legs) grew up fast and got messy. So we wrote a clean blueprint for a better one — Skater-Rig v2 — and then built it: new bones, new physics for floppy arms and stretchy legs, a rulebook that makes bad poses impossible, and a new editor to pose him in. That took three long days. This week the new skeleton was wired into the real game, the hand-inked skateboard art came back, and every move — pushing, crouching, ollies, backflips, grinding, landing — now runs on it.

What's next? Flip the switch so the new version is THE game everyone gets (that's literally in progress right now), then teach the skater more moves — board grabs, idle animations, new tricks — and start building the nine new worlds for the paid version.

Rig v2 is in the game

Not a demo, not a side build — the real game loop drives the new skeleton, verified frame by frame.

The switch is being flipped

v1.1.0 makes rig v2 the default build. The old rig stays on disk, buildable, until we delete it on purpose.

Next up: more moves

The engine is done. What's left is mostly content — poses and cycles from the spec's wish list.

02

The story so far — a two-week timeline

Fourteen days, 164 commits. Here's the whole run, stitched together from the changelogs, the work log, and every roadmap page that came before this one.

  • Jul 8 – 12

    The game gets built

    KICK/PUSH starts life as one giant hand-inked HTML file (kick-push.html, 1.7 MB of game). It then gets restructured properly: small source files under src/, a build script that squeezes everything back into one deployable file, levels, audio, tricks, pickups.

  • Jul 13

    A new rig and a BETA skater

    The first big character rebuild — a new-style rig behind a BETA button, posed in a new dev tool that would grow into the Skater-Rig editor.

  • Jul 14 – 15

    Milestones M0–M5, rapid fire

    Toes-down feet fix, pose saving, a real pose workflow, animation clips, the in-game clip player, floppy physics arms, and crouch/backflip controls. Five changelogs in two days.

  • Jul 16

    The animator overhaul

    Editor v0.5.0: toolbar tools, bone overlays, key poses, force-hit stars. The riding animation becomes canon — one source file the whole game derives from. First roadmap page ships.

  • Jul 17

    One cycle, one file — enforced

    A test gate now fails the build if the riding cycle is ever copy-pasted anywhere. Roadmap v2.

  • Jul 19

    The big Saturday: how riding feels

    34 commits. Swipe-rate becomes the throttle (swipe harder = genuinely faster), the four-anchor drive system (Rest/Slow/Coast/Push), side-paint mode for posing, and game v1.0.1. Roadmaps v3–v5 and a week-in-review page.

  • Jul 20, early

    The game turns out to be LIVE

    Batch 6 lands (v1.0.2) — and the deploy pipeline is discovered already working: push to GitHub, Cloudflare Pages builds it, play.usefulpurpose.com serves it. Byte-for-byte verified.

  • Jul 20, morning

    Batch 7: triggers become data — v1.0.3 ships

    The animation trigger ladder becomes clip data instead of hardcoded if/else, proven identical by a 167,616-case test. v1.0.3 goes live. Roadmaps v7/v8 and the nine-worlds business plan.

  • Jul 20, rig-v2 day 1

    The spec becomes an engine

    rig-spec-v2.md goes from paper to running code in one day: the part model, matrix math with the stretch fix, springs and world-space drag, procedural transitions, a state graph, joint limits, a pose linter — plus a brand-new spec-first character (34 parts, fingers included) and the v1 animations migrated onto it. 12 test gates green by midnight.

  • Jul 21, day 2

    Air, the editor, and speed-simplify

    The jump arc becomes the animation clock (ollies land their catch frame at any height), winding backflips/frontflips live on the root bone, the full §9 editor ships as Skater-Rig v2, and the lost-inbetweens speed effect gets ported. 15 gates.

  • Jul 21, day 3

    Game integration + the art pass

    The real game loop drives rig v2 through its existing seams — no game code edited. The canonical state graph gets its ground half, board attachment is finally consumed, and the hand-inked v1 skateboard is wrapped in as the board art. 16 gates, verified live in the browser.

  • Jul 21, tonight

    The default swap — v1.1.0

    Rig v2 becomes THE game. Old rig stays on disk, buildable behind a flag, until it's retired on purpose. This page is the state of the world as that lands.

What's completed

Scored against the rig-v2 spec (docs/rig-spec-v2.md), section by section. Everything below is built and guarded by automated tests — 16 gates, 168 individual checks, run on every npm test.

Spec areaStatusIn one line
§1–3 Character & hierarchydone 34-part spec-first skater (pear body, big hands, fingers), board as a sibling of the hips, all limbs drawn straight-down per the rest-pose rule.
§4 Data modeldone Flat part list with stable IDs; poses and cycles are one type (1 key or 8 keys).
§5 Transform & stretch mathdone Matrix stack; stretch doesn't inherit (the old knee-gap bug is dead); stretch lives in additive tracks, never in keys.
§6 Procedural dragdone Floppy arms lag in world space, clamp at 60°, die on landing; falling arms stretch overhead.
§7.1–7.3 Regions, layers, speed blenddone Region masks, a weighted layer stack with buried-layer detection, and speed variants that blend instead of switching.
§8 All eleven guardrailsdone Joint limits clamped last, shortest-path blending with the winding escape hatch for flips, procedural transitions from the evaluated pose, z-order snapping, the pose linter, the legal-moves state graph, explicit board attachment.
§9 Editorshipped Hierarchy, scrubbable readout with world values, region toggles, layer panel with per-region burial warnings, read-only transition preview with lint flags, pose library + mirror, state-graph view, air preview.
§10 Migrationdone All eight ordered steps executed; every "inconsistency to expect" was found and fixed (several by test gates that now keep them fixed).
Air systemdone The jump arc is the animation clock; flips complete their spin by touchdown no matter how short the hop.
Game integrationdone The shipped game loop drives all of the above; board/face art pass included.
04

What's left to do

The honest list. Nothing here blocks the game — it's ranked by how visible it is to a player.

ItemSizeWhy it matters
The default swap in flightsmall v1.1.0: rig v2 becomes the shipped game. Happening now.
Board-grab posesmall The one visible regression: double/triple-jump grabs currently hold the ollie tuck. One authored pose + one graph edge fixes it.
Grind & manual loopsmedium The spec's own warning: "Grind and Manual need their loops or they look dead as static poses." Grind today matches v1 (a held pose), but a balance-wobble loop would bring the rail alive.
The §7.4 content batchlarge ~12 poses (tuck, manual, handstand, superman, nose/tail grab, celebrate, brace, fall, getting-up…) and ~7 cycles (riding slow/fast banks, devil hands, tumble, idle variants, walk). Pure authoring in the v2 editor — no engine work.
Editor nicetiesmedium Live preview (clip looping over scrolling ground), general onion skinning, sprite paint-by-side. Pan/zoom already exists; onion skin exists inside transition preview.
Force-hit stars portmedium v1's trick for making key poses land crisply. Metadata already carried on v2 clips; the pull itself isn't ported yet.
Ground anchor consumptionsmall Handstand-family poses need the root to sit at the hands, not the feet. The data field exists; nothing reads it yet. Only matters once those poses exist.
Real face inkmedium The face parts (eyes, mouth) are empty sockets waiting for a face-capable head drawing. Needs Minder's pen — the hatched-shades head is the shipped look meanwhile.
Nine-worlds groundworklarge Before world 2 exists: the svg-to-art.js pipeline and a level registry. Then worlds 2–9, the two-gate paywall, Capacitor (mobile, $4.99) and Electron (Steam, $8.99) shells.
