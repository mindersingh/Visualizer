THE PARITY PLAN, v3

The original parity plan was written at noon on July 21. By 9 p.m. the same day, eleven commits had taken the v2 editor from v0.1.0 to v0.4.1 — and almost none of them were on the plan. This page scores what actually landed, re-audits the matrix against the editor that exists now, and re-sequences what's left. The full story of every commit is on the devlog.

since plan v1: 11 commits · tester v0.1.0 → v0.4.1 engine fixes shipped: 2 (both in the live game) Verdict: the port list survived intact — the sprint built things the plan never listed
plain words first

What happened. Instead of porting v1 comforts, the sprint made the v2 editor good at the thing that matters most: posing. Click a limb to select it, swing it without tearing the chain, pin a foot to the deck and pose the hip around it, drag pins on the board itself and let IK glue the hands and feet there live. None of that was in the plan — the plan assumed posing was a solved problem and speed was the gap.

What it proved. Building the editor found two real engine bugs (channels first keyed mid-cycle were silently dropped — in the tester and the shipped game). The editor is doing its job as the rig's first customer.

What didn't change. The six-item port list. Live preview, autosave, save-to-repo, onion skin, playback speed, force-hit stars — all still open, all still the right list. And undo is now more urgent, not less: the editor can do much more per minute, which means it can lose much more per mistake.

Landed: posing power

Gizmos, structure lock, foot pins + locks, board pins with live IK glue, a real playhead, the protractor ring, the body blob toggle.

Still open: the port six

Live preview, session autosave, save-to-repo, onion skin, playback speed, force-hit stars. Untouched since plan v1.

Next: safety, then content

Undo/redo and autosave before the §7.4 content batch. The sprint sharpened the knife; don't run with it yet.

the honest score Plan v1 said: port six things, then add undo. The sprint did neither — and was right to. It built posing ergonomics the plan under-scoped because the plan graded the editor on v1's rubric (comforts around a working tool) when the real gap was the tool itself. The lesson for v3: the port list is still correct, but it's batch two. Posing came first because posing is what the §7.4 content batch actually is.

03

The port list, re-ordered

Same six features as plan v1 — the sprint validated the list by not making any of it unnecessary. What changed is the order: safety first, because the editor is now powerful enough to lose real work.

#FeatureSizeWhat changed since plan v1
1Session autosavesmall Was #2. A session now includes pins, locks, and bakes — snapshot the whole editing state, not just the clip JSON.
2Undo / redo (from the QoL list, promoted)medium Board pins bake rotation keys across all eight keys in one action. One wrong bake with no undo = re-posing a cycle. This ships with, not after, autosave.
3Save to repo, v2-nativesmall POST /api/save-clip-v2 → tools/dev-v2/clips/<name>.json, server-side lintClip. Unchanged, but now blocking real output.
4Live previewmedium Ground-scroll toggle + cadence knob, respecting the loads-paused default. Pins stay glued during preview — that's the whole demo.
5Onion skin + playback speedsmall Bundled — both are one-evening features hanging off the playhead.
6Force-hit starsmedium After a shipped clip uses stretch-aware locks. The push foot-plant is still the likely first customer.

The order, v3

Plan v1's batch A–E, rebuilt around one fact: the sprint already delivered a batch nobody planned — call it batch Ø, posing power — and it came first because it was right to. The rule stands: everything that speeds up the §7.4 content batch comes before everything that doesn't.

BatchContentsExit test
Ø — posing landed Gizmos · structure lock · foot pins/locks · board pins · playhead · protractor · body blob toggle · two engine sampling fixes Pose a full key with the mouse only, feet glued to the deck, without tearing a chain. Passes today.
A — safety Session autosave · undo/redo · save-to-repo v2 endpoint (with server-side lint) Kill the tab mid-edit with three pins set, reopen, keep working. Bake, regret it, Cmd-Z. Save twenty clips without touching a clipboard.
B — review Live preview · onion skin · playback speed · copy/paste pose · duplicate clip Author one brand-new 8-key cycle start-to-finish without leaving the editor or squinting.
C — content The §7.4 batch itself: boardgrab first, then grind wobble, idles, celebrate, the rest Every trick the game can trigger has a real pose; the graph has no placeholder nodes.
D — feel Force-hit stars · feel-knobs panel · diff-before-export The push foot-plant visibly snaps; tuning a spring doesn't require editing source.
E — polish GIF export · phone hand-off · release script · gate timings · UI-inventory gate for v2 A clip review happens on a phone; a release is one command plus a deliberate push.
what parity means, v3 edition Plan v1 said parity ends with half of v1's control count and all of its speed. One day later the v2 editor already does things v1 never could — live IK glue, joint-limit protractors, structure that can't tear. The target moves accordingly: parity isn't the finish line anymore, it's the floor. The measure of success is unchanged and now closer: the next twenty clips get authored faster than the last twenty were.
